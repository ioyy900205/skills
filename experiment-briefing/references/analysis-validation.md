# 分享前分析 QA

这份 QA 在生成最终汇报前运行。目的不是增加流程，而是避免“页面做得很好，口径却错了”。

## 1. 问题与范围

先确认：

- 报告回答的是用户真正的问题，不是更容易回答的替代问题。
- 人群/样本/数据集/项目阶段定义明确。
- as-of 日期、时间窗、时区明确。
- 比较对象处于可比条件。

## 2. 数据完整性

检查：

- 是否有意外缺失条件、空值或未同步来源。
- “没有记录”是否被误写成“数值为 0”。
- 是否有重复样本/重复记录造成 double counting。
- 是否遗漏失败样本、退出样本或只保留成功者。
- 当前周期是否尚未结束，却与完整历史周期直接比较。

## 3. 指标与分母

关键百分比至少确认一次分子和分母。

特别警惕：

- 分母在不同条件间变化。
- 把百分比点变化写成百分比变化。
- 对已经聚合的平均数再次等权平均。
- 不同样本量的组被当成同权。
- 指标定义在报告中途发生变化。

## 4. 比较公平性

对 baseline / new model / seen-unseen / 不同数据源的比较，确认：

- 输入数据一致或差异已声明。
- 评测协议一致。
- 样本规模可比。
- causal/noncausal、在线/离线、不同算力/延迟等关键约束没有被混在一起。
- 只在一个版本有利的筛选规则没有悄悄出现。

## 5. Sanity checks

对最重要的 3–5 个数字做独立检查：

- 总数是否与子项加总一致。
- 数值量级是否合理。
- 0% / 100% / 巨幅跳变是否真有证据。
- 用另一种简单计算路径能否近似复现。
- 随机抽几个样本能否从原始记录追到汇总。

无法验证时不要写“已验证”；在限制里注明。

## 6. 图表误导检查

快速阅读者是否可能因为图本身得出错误结论：

- 轴/单位/时间范围清楚。
- 对比图尺度一致。
- 颜色不是唯一状态编码。
- 缺失值与 0 区分。
- 图标题写的是图真正支持的结论。
- 没有裁掉不利条件或只画最好样本。

## 7. 叙事与替代解释

逐条看关键结论：

- 证据真的支持这句话吗？
- 是否有合理的替代解释？
- 是否把相关写成因果？
- 是否把一次结果外推到未测试人群/场景？
- 样本量是否足以支撑强结论？

如果证据不足，降级措辞或列进 Open Questions。

## 8. 项目汇报专用检查

- “完成”是否有来源，而不是计划中的完成日期。
- activity 是否被误写成 outcome。
- 风险和 issue 是否区分。
- owner / due / status 是否来自来源；未知写 TBC。
- “无新进展”是否只是因为本次没有访问到相关来源。
- 与上一版相比的变化是否能追溯。

## Blocking issues

下面这些问题出现时，优先修复再交付：

- 核心数字无法追溯。
- 关键比较分母/协议不一致且未披露。
- 成功样本筛选造成明显偏差。
- 已知缺失被当成 0。
- 报告给出来源不支持的根因/项目状态/owner。
- 页面结论与底层表格不一致。

修不了时，把它们直接写进限制和 Open Questions。
