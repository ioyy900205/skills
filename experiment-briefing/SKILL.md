# Experiment Briefing

目标只有两个：

1. **领导 30 秒拿到结论。**
2. **自己三个月后能追溯每个数字怎么来的。**

用分层解决两者冲突：前面只放结论和关键证据，后面放全条件、口径、限制和复现信息。

## 五条硬规则

1. **运行结果是唯一真相源。** 页面中的实验数字从运行目录或结构化汇总读回；不要手敲实验结果。
2. **改生成器，不改生成后的 HTML。** 报告必须能重新生成。
3. **覆盖完整证据。** 不只展示成功案例；区分“未运行/未合成”和“运行了但得零分”。
4. **结论不能强于证据。** 阴性结果照写；数据推翻预设叙事时，重写叙事。
5. **限制和复现属于正文。** 不把关键 caveat 藏在附录或 README 里。

## 工作流

### 1. 先检查现有项目

先看运行目录、已有汇总文件、已有报告生成器和项目约定。优先复用项目已有的统计函数、设计系统和目录结构，不要复制出第二套实现。

如果只有日志、零散图片或逐样本结果，先整理出结构化 JSON/CSV，再做页面。不要从截图或人工抄表直接生成最终数字。

### 2. 选择报告模式

默认输出“单文件自包含 HTML”。

如果核心证据是大量音频/视频，改用“HTML + assets 相对路径”，媒体使用延迟加载，避免把页面膨胀到几百 MB。

如果用户只是要文字总结、周报、PPT 或 Notebook，而没有网页交付需求，不要把任务强行转成 HTML。

### 3. 从生成器开始

优先从 `assets/report_template.py` 起步，并复用：

- `assets/report_html.py`：HTML、主题、表格和图片内嵌
- `assets/charts.py`：内联 SVG 图表
- 项目已有的等价模块：如果已经存在，优先用项目版本

每个实验数字都应在代码里由数据计算得到。正文里的数字也一样，不要让图表读数据、正文却写死。

### 4. 按固定信息层级组织

默认顺序：

**Hero → 必要的概念铺垫 → 方法 → 主结果 → 全条件证据 → 边界归因 → 口径与限制 → 复现**

可以删掉不需要的节，但不要把限制藏到最后才第一次出现，也不要把长方法说明放在结论前面。

标题写**结论**，不是写“XX 实验报告”。

KPI 写“数字 + 比较/含义”，不要只放孤立数字。

每张主图后面写 3–5 条“这张图说明什么”，至少包含一条限定、失败或反直觉发现。

更详细的页面结构和视觉约束见 `references/report-structure.md`。

### 5. 先判断证据类型，再写结论

遇到归因、消融、误差分解、失败原因、信息上限等内容时，读取 `references/evidence-and-claims.md`。

特别注意：

- 恒等式/精确记账可以说“占多少”。
- 构造条件可以说“输入是什么”。
- 消融/干预只能说“改掉它会怎样”，多个消融结果通常不能横向相加成总归因。
- 输入本身不可区分造成的失败，不应写成模型能力不足。
- 信息充足但模型失败，才是模型真正需要跟进的边界。

### 6. 验证成品

生成后执行：

~~~bash
node <skill>/scripts/check_page.cjs <报告目录>/index.html --shots /tmp/report-shots
~~~

然后**实际看截图**。自动体检能抓溢出、外链、tab、主题和 JS 错误，但抓不到“图太挤”“信息层级不清”“领导第一屏看不懂”。

如果当前环境没有 Playwright，不要跳过不说；明确记录哪些浏览器级检查没执行。

验证、自包含、README、媒体和端口分享细节见 `references/delivery-and-validation.md`。

### 7. 交付一个目录

默认交付：

~~~text
reports/<主题>/
  index.html
  README.md
  data.json / *.csv
  assets/          # 只有音频、视频或必须外置的媒体才需要
~~~

README 至少包含：起因/上游报告、完整重跑命令、主要输入与版本、报告体积、与上一版差异。

如果用户要求给同事一个链接，再使用 `scripts/serve_report.sh`。不要默认开放端口。

## 完成标准

交付前确认：

- 页面中的实验数字都有结构化来源，没有人工抄写的最终结果。
- Hero 单独看就能回答“做了什么、最重要发现是什么、规模多大”。
- 主结果没有挑样本；失败、未运行和缺失条件区分清楚。
- 结论措辞与证据强度匹配。
- 限制在页面里可见。
- 图表有等价数字表或可追溯数据导出。
- 报告能由生成器重建。
- `check_page.cjs` 已通过并查看过截图，或明确说明未能执行的检查。
- README 和 CSV/JSON 数据导出已生成。
